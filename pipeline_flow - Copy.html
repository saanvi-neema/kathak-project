System diagram — dance analysis dashboard

How a performance becomes a report

An uploaded video and a live webcam session enter differently and finish differently — but everything in between, the actual chakkar/mudra/rasa/timing/tatkaar analysis, is the exact same code running on the exact same shape of data.

Upload

One finished video, analyzed once, top to bottom. Simple, but you only see results after the whole file is processed.

Live

The browser records in ~1.5s chunks; each one is decoded, appended to a rolling buffer, and the full buffer is re-analyzed — so feedback updates as you dance, until you click Stop.

Hardware feedback

After scoring, per-finger mudra accuracy is read by a threshold gate — the same numbers shown on the dashboard. Only fingers below the threshold (e.g. 20% accuracy) trigger a buzz, so the glove and dashboard always agree. This prevents firing on minor deviations and lets the dancer converge. Once corrected, the camera sees the new hand position in the next chunk and the motor stops. A closed physical loop.

What the five checks are

Chakkar
Counts spins from shoulder rotation and scores landing quality — count accuracy, ending orientation, controlled vs. abrupt stop.
Mudra
Identifies held hand gestures with a trained classifier, then checks the shape against reference rules.
Rasaunvalidated
Reads facial expression against the navarasa (nine classical emotions) on a fixed 1-second clock.
Timing & Taal
Checks wrist-movement peaks against the music's beat grid, and chakkar landings against the taal cycle's sam.
Tatkaarunvalidated
Detects rhythmic footwork as a sustained run of closely-spaced audio strikes — no camera view of the feet required.

Inside Analysis: how each check actually works

The flowchart's "Analysis" box treats all five checks as one step. They're not one algorithm — each reads a different signal and asks a different question.

Chakkar

body pose

Shoulder angle, tracked frame by frame, gets unwrapped into a continuous rotation signal. A sustained turn is segmented out as one spin event, and nearby segments within a small gap are merged so one spin doesn't fracture into several. Each event is scored on three things: how close the rotation lands to a clean number of turns, how far the ending orientation drifts from the starting one, and whether the stop was controlled or abrupt (from angular deceleration right at the end).

real signal · chakkar_03.mov · ~10 turns over 12.1s

Mudra

hand skeleton

A mudra is a held pose, so it's found by looking for stillness, not motion: a window where hand-landmark movement drops and stays low long enough to count. Inside that window, finger-curl angles, thumb-to-fingertip distances, and finger-spread are averaged and handed to a small trained classifier, which names the closest-matching mudra. Separately, that mudra's own shape rule (which fingers should be extended vs. curled) is checked against the same measurements — so rule agreement (does the shape look internally consistent) and identification accuracy (was the guess actually right) are two different numbers.

Rasaunvalidated

face model

Sampled on a fixed one-second clock, not triggered by any particular movement. In each window, 52 named facial-expression parameters — from a separate face-tracking model, not the body/hand skeleton — are averaged and compared against reference criteria for each of the nine classical navarasa. A real smile paired with relaxed brows, for example, reads as Hasya (joy). The closest match is reported along with anything about it that didn't fit cleanly.

real blendshape scores · one 1s window · mudra_01.mov

Timing & Taal

body pose + audio

Both share one audio beat grid, detected once from the track's tempo. Timing checks whether gesture emphasis (peaks in wrist speed) statistically lines up with that grid over rolling 8-second windows, and separately flags a performance that ends noticeably off the music's last beat. Taal goes further, but only if you supply the taal and where the first sam falls: each chakkar's landing time is measured against the nearest sam using that taal's real cycle length (Teentaal's 16 beats, Jhaptaal's 10), not just the raw beat grid.

real wrist speed (dots = peaks) vs. real beat grid · 10s window

Tatkaarunvalidated

audio only

Deliberately audio-only, not skeletal: a tatkaar's whole point is the percussive sound of the strike, and camera framing can't be trusted to keep feet in view anyway. The track's sound onsets are detected, then a sustained run of closely-spaced onsets — many strikes in a row at roughly the same pace — is reported as one phrase, with a strike count and rate, rather than trying to match individual bols one by one.
